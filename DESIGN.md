# Design Decisions

## 1. Отмена устаревших запросов

Для отмены устаревших HTTP-запросов используется `AbortController`.

При каждом изменении поискового поля увеличивается версия запроса (`latestVersion`),предыдущий запрос отменяется вызовом `controller.abort()`.

После завершения debounce создаётся новый `AbortController`,его `signal` передаётся в `searchCountries`, а затем в `fetch`.

В `searchCountries` пользовательский сигнал объединяется с сигналом таймаута через `AbortSignal.any()`. Это позволяет отменить запрос как при новом вводе пользователя, так и при превышении времени ожидания.

Дополнительно используется проверка актуальности ответа: сравниваются версия запроса, текущий поисковый текст и контроллер. Это защищает интерфейс от обновления устаревшими результатами или ошибками.

Используется AbortController, а не только флаг актуальности ответа, т.к. флаг позволяет проигнорировать устаревший ответ, но не прекращает выполнение HTTP-запроса. Запрос продолжает использовать сетевые ресурсы, даже если его результат больше не нужен.

`AbortController` позволяет действительно отменить запрос на стороне браузера. Дополнительная проверка версии нужна для защиты от ситуаций, когда ответ успел завершиться одновременно с отменой или относится к предыдущему поиску.

Таким образом, `AbortController` отвечает за отмену ненужной сетевой операции, а проверка версии — за актуальность отображаемых данных.

Основная реализация: `searchHandler.ts`, `searchCountries.ts`.

## 2. Выбор задержки debounce

Для поиска выбрана задержка 500 мс.

Debounce предотвращает отправку HTTP-запроса после каждого нажатия клавиши. Новый запрос запускается только после того, как пользователь перестал вводить текст на 500 мс.

Это компромисс между отзывчивостью интерфейса и количеством сетевых запросов.

- Если убрать debounce, запрос будет отправляться после каждого изменения поля. Это увеличит количество HTTP-запросов и нагрузку на сервер.
- Если значительно увеличить задержку, например до 1500–2000 мс, интерфейс будет казаться медленным: пользователю придётся дольше ждать начала поиска.
- Задержка 500 мс позволяет сократить количество лишних запросов, сохраняя приемлемую скорость поиска.

Реализация: `debounce.ts`, использование в `searchHandler.ts`.

## 3. Сложность алгоритмов (Big O)

### mapCountryResponse

Функция `mapCountryResponse` преобразует объект страны, полученный от API, в объект с данными, необходимыми для отображения карточки.

Основная часть операции выполняется за постоянное время. Массив языков обрабатывается отдельно, поэтому сложность зависит от количества языков страны.

Обозначим количество языков через `n`.

- Временная сложность: O(n) — необходимо обработать каждый элемент массива языков.
- Пространственная сложность: O(n) — создаётся новый массив языков в результирующем объекте.

## 4. Принципы чистого кода

В проекте применяются следующие принципы:

### Осмысленные имена (Meaningful Names)
- `searchCountries.ts` — переменные `timeoutSignal`, `combinedSignal`, `response` описывают хранящиеся в них данные.
- `Card.ts` — имена `flag`, `capital`, `region`, `population` соответствуют предметной области.

### Single Responsibility Principle (SRP)

Каждая функция отвечает за отдельную задачу:

- `debounce.ts` — управление задержкой вызова функции.
- `searchCountries.ts` — выполнение HTTP-запроса и обработка HTTP-ответа.
- `mapCountryResponse.ts` — преобразование данных API в модель карточки.
- `handleSearchError.ts` — определение типа ошибки и формирование сообщения.
- `searchHandler.ts` — управление поисковым процессом и взаимодействием с DOM.
- `Card.ts` — создание DOM-элемента карточки страны.

### DRY (Don't Repeat Yourself)

- `debounce.ts` — была реализована функция, которая повторно использует логику задержки вызова. Это позволяет применять одинаковый механизм ограничения частоты вызовов в разных частях приложения без дублирования реализации таймеров.
